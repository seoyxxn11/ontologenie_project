# 4. 시연 시나리오

프레스 공정 공장의 ERP·MES 원천 데이터(팀이 만든 합성 데이터, 기준 시각 2026-10-30 14:00)를 연결해, AI 제안으로 온톨로지를 만들고 Agent로 설비 고장에 대응하는 흐름입니다. 시나리오 번호는 [README](../README.md) 2절(S1~S7)과 같습니다.

최종 발표에서 실제로 진행하는 약 5분 시연은 4.2입니다. 4.3부터는 발표 시연에서 다루지 않는 기능까지 포함한 기능별 시나리오입니다.

화면 이름·버튼 이름·위치는 2026-11-16 운영 서버(`https://ontologenie.com`) 관리자 화면에서 확인한 그대로입니다(4.2는 2026-11-17~18에 확인). 위치는 PC 브라우저(가로 1440px 안팎) 기준입니다.

## 4.0 시연 전 준비

이미 분석·매핑·수집이 끝난 환경에서는 아래 준비 표를 확인합니다. 새 설치나 첨부 플랫폼 덤프 복원 직후에는 먼저 다음 `빈 플랫폼에서 시연 상태 준비`를 수행합니다. 화면에 적힌 운영 서버의 건수·객체 번호는 2026-11-16~18에 확인한 예시이고 신규 환경의 합격 기준으로 쓰지 않습니다.

| 항목 | 확인 |
| --- | --- |
| 서비스 주소 | `https://ontologenie.com` (Chrome 권장) |
| 계정 | 관리자 1개(ADMIN). 민감 값 열람을 보여 줄 때만 생산기획자(PLANNER) 계정을 `계정·권한`에서 따로 만듭니다. 비밀번호는 팀이 보관 |
| 원천 | ERP·MES 원천 서버가 켜져 있고, 데이터 연결 화면에서 두 원천이 모두 `수집 접속 확인됨` |
| 수집 | Kafka Connect 커넥터 2개가 RUNNING, batch의 CDC 소비자가 켜져 있음 |
| LLM | GMS 키가 유효하고 크레딧이 남아 있음(AI 분석·Agent 모두 사용) |
| 시연 데이터 | 원천이 `ai/data/data-v1.0` 상태. 전에 CDC 시연을 했다면 `ai/data/scenario-v1.0/cdc_99_restore.sql`로 되돌림. S5에서 쓸 `s5_fix.sql`은 아직 적용하지 않음 |
| 분석 상태 | 운영 참고값은 11-16 기준 전체 132·검토 대기 63. S2·S5를 먼저 보여 줄 때는 `금형 → 품목`, `작업지시 → 수주 상세`의 검토할 후보를 남깁니다. 5분 발표만 할 때는 그 발표에 필요한 관계를 먼저 승인·적재합니다 |

### 빈 플랫폼에서 시연 상태 준비

첨부 플랫폼 SQL은 V29 스키마·역할·권한·기본 Action을 복원합니다. 계정·원천 연결·분석 후보·객체·관계·계획은 복원하지 않습니다. 따라서 다음 준비가 끝나기 전에는 4.2의 객체 링크를 바로 열 수 없습니다. 원천은 [빌드·배포 절차](1-build-deploy.md#원천-erpmes-서버)의 `setup.sh` 적재 또는 [덤프 복원](3-db-dump/README.md#복구) 중 한 방법만 사용합니다.

1. **관리자 로그인**: backend 기동 때 `AXCORE_INITIAL_ADMIN_LOGIN_ID`·`AXCORE_INITIAL_ADMIN_PASSWORD`로 생성된 ADMIN으로 `/login`에 로그인하고 임시 비밀번호를 변경합니다. 관리자를 만들지 못했다면 기동 설정과 로그를 확인합니다. 사용자 정보는 첨부 덤프에 들어 있지 않습니다.
2. **원천 두 개 등록**: 상단 `데이터 연결` → `+ 원천 등록`. 아래 값을 입력하고 오른쪽 아래 `등록`을 누릅니다. `접속 대상`은 `호스트:포트/DB` 한 줄이고 포트를 생략하면 5432가 되므로 원천의 15432를 반드시 적습니다.

   | 화면 입력 | ERP | MES |
   | --- | --- | --- |
   | 원천 이름 | `ERP 운영 DB` | `MES 운영 DB` |
   | 원천 코드 | `ERP_MAIN` | `MES_MAIN` |
   | 유형 | `구조화 데이터`(PostgreSQL) | 같음 |
   | 접속 대상 | 실제 ERP 주소 뒤에 `:15432/erp` | 실제 MES 주소 뒤에 `:15432/mes` |
   | 수집 계정 이름 | `platform_ro` | `platform_ro` |
   | 수집 계정 비밀번호 | 해당 원천의 `PLATFORM_RO_PASSWORD` | 해당 원천의 같은 변수 값 |
   | AI 분석 계정 이름 | `platform_ai` | `platform_ai` |
   | AI 분석 계정 비밀번호 | 해당 원천의 `PLATFORM_AI_PASSWORD` | 해당 원천의 같은 변수 값 |

   `접속 정보` → `연결 다시 확인`에서 수집·AI 계정이 모두 접속됐는지 확인합니다. 원천 관리자 `source_admin`이나 복제 계정 `platform_cdc`를 이 조회 계정 칸에 넣지 않습니다. SSL은 백엔드 기본 `require`, 원천 보안 그룹과 `pg_hba.conf`는 메인 서버 IP를 허용해야 합니다.
3. **승인 전 CDC 준비**: [CDC 연결 순서](1-build-deploy.md#cdc-연결-순서-infracdcreadmemd)에 따라 커넥터·태스크 두 개 RUNNING, 원천 복제 슬롯 active를 확인합니다. `AXCORE_CDC_CONSUMER_ENABLED`·`AXCORE_CHECK_SYNC_ENABLED`를 켠 실행용 설정이 batch에 반영되고 소비자 기동 로그가 나오는지 확인합니다. `.env.config`만 편집하고 batch에 반영하지 않은 상태로 다음 승인 단계로 넘어가지 않습니다.
4. **분석 대상 선택**: `AI 관계 제안 받기` → `등록된 원천`에서 ERP·MES를 번갈아 선택합니다. 표를 누른 뒤 컬럼 표 머리글의 `전체`로 그 표의 조회 가능한 컬럼을 선택합니다. 검색을 사용했다면 검색을 지워 모든 컬럼이 선택됐는지 확인합니다. 다른 표도 같은 방식으로 고르고 아래 `n개 원천·n개 테이블·n개 컬럼`을 확인한 뒤 `분석하고 후보 받기`를 누릅니다. 최소한 아래 자료를 포함하며, 상세 이력 탐색까지 보여 줄 때는 허용된 관련 표도 함께 분석합니다. 읽기 권한이 없는 표·금지 컬럼은 선택 범위에 억지로 넣지 않습니다.

   | 목적 | 필요한 원천 자료 |
   | --- | --- |
   | 거래처·수주·품목 | `erp.vendor`, `erp.sales_order`, `erp.sales_order_line`, `erp.item` |
   | 설비·작업·공정 조건 | `mes.equipment`, `mes.work_order`, `mes.work_order_operation`, `mes.routing` |
   | 비가동·진동·정비·품질·실적 탐색 | `mes.downtime`, `mes.sensor_reading`, `mes.maintenance_order`, `mes.defect`, `mes.production_result` 등 조회 가능한 관련 표 |
   | S5 금형 미연결 검사 | `mes.die`와 `erp.item` |

5. **객체 속성 검토·승인**: 분석이 완료되면 `연결 규칙` → `객체 속성`에서 필요한 유형·속성·원천 매핑을 검토하고 사유를 입력해 승인합니다. `설비`, `작업지시`, `작업지시 공정 배정`, `공정 기준`, `거래처`, `수주`, `수주 상세`, `품목`에 대응하는 후보가 있는지 봅니다. AI가 붙인 이름은 달라질 수 있으므로 원천 표·컬럼과 연결·변환 규칙으로 식별합니다.
6. **관계 규칙 확인·승인**: `매핑`에서 아래 연결이 가능한지 검사 결과와 표본을 확인합니다. 잘못 제안됐거나 빠진 규칙은 `규칙 후보 수정` 또는 `직접 관계 제안`으로 검토·시험한 뒤 승인합니다. AI 신뢰도만으로 승인하지 않습니다.

   | 시연 연결 | 검토할 원천 조건 |
   | --- | --- |
   | 거래처 → 수주 | `vendor.vendor_code`와 `sales_order.customer_code` |
   | 수주 → 수주 상세 | `sales_order.so_no`와 `sales_order_line.so_no` |
   | 수주 상세 ↔ 작업지시 | `so_no`와 `work_order.so_ref`의 숫자 추출값, `item_code`와 `product_code`의 일치 |
   | 작업지시 → 공정 배정 | `work_order.wo_no`와 `work_order_operation.wo_no` |
   | 공정 배정 → 설비 | `work_order_operation.equipment_code`와 `equipment.code` |
   | 작업·공정 → 공정 기준 | `work_order.product_code`와 `routing.product_code`, 배정 `op_seq`와 기준 `op_seq` |

   이 표는 원천 필드 기준의 점검표입니다. 관계 방향·유형·생성된 속성 코드는 실제 후보와 검사 결과로 확인합니다. S2·S5 승인 장면을 함께 보여 줄 경우 해당 후보를 남겨 뒀다가 시연 순서에 맞춰 승인하며, 4.2 시작 전에 필요한 경로의 적재를 끝냅니다.
7. **그룹·표시 이름 설정**: ⚙ → `객체 유형`에서 ERP 영업·수주 유형의 조회 그룹은 `영업·구매·재고 (SALES_SUPPLY)`, MES 생산·설비 유형은 `생산·설비 (PRODUCTION)`처럼 준비한 조회 범위에 맞춥니다. `대표 속성`에는 각 유형의 이름 속성(설비 이름·거래처 이름 등)을 지정하고 저장합니다. 그룹 없는 유형은 ADMIN만 보며 Agent 전송 범위에서는 빠집니다. 저장 뒤 다시 읽기가 끝나 표시 이름에 반영됐는지 확인합니다.
8. **적재 완료·발표 경로 확인**: `데이터 연결`의 최근 전체 읽기와 수집 이력에서 완료를 확인합니다. `업무 데이터`에서 `한결모터스`, `OD-2610-021`, `JB2610-0141`, `P103`, `P101`, `P201`을 이름·원천 키로 검색합니다. `관계 보기`를 따라 거래처 → 수주 → 작업지시 → 공정 배정 → P103에 닿는지 확인하고, P103 `정비중`, 공정 20·30 `중단`·잔량 3,200, PRS·최소 400톤, P101 400톤·P201 300톤을 대조합니다. 관계나 속성이 없으면 분석·승인·수집을 먼저 보완합니다.
9. **현재 환경의 바로 가기와 대화 준비**: 검색 결과에서 객체를 열고 브라우저 주소의 `object=` 값을 기록합니다. 최소 거래처·수주·P103의 주소를 준비해 아래 운영 예시 `#3552`, `#3235`, `#3` 대신 사용합니다. 이후 4.2의 시작 질문과 내 질문 A·B를 준비하고, 다른 환경에서 만든 브라우저 질문 저장값이 자동 이동하지 않는 점을 확인합니다. 장애 대체용 예시 재배정 계획이 필요하면 현재 환경에서 조건을 검증해 한 건 미리 생성합니다.

준비 완료 기준은 위 원천 키·값·관계와 정상 수집·질문 결과입니다. 운영 예시의 후보 132건·검토 대기 63건·객체 ID·연결 609건과 숫자가 똑같은지는 기준이 아닙니다. GMS 분석 결과는 실행마다 달라지므로 이 준비 과정을 생략한 동일 시연 상태의 자동 복원은 제공하지 않습니다. 기본 상태에서 검토를 거쳐 만드는 절차이며, 새 환경 전체 리허설은 발표 전에 담당자가 실행합니다.

## 4.2 최종 발표 시연 (약 5분, S3·S4)

소개 영상 마지막에 나온 AI 업무 도우미 대화에서 시작해, 고객 문의 한 건의 대응 계획을 남기는 데까지 갑니다. 제안·승인·연결 규칙은 발표 자료에서 설명하고 이 시연에서는 다루지 않습니다(4.4~4.6 참고). 목표 시간은 4분 50초입니다.

영상은 영업 담당이 고객에게 "대응 계획을 확인해 다시 안내드리겠습니다"라고 답하며 끝납니다. 시연은 발표 앞부분에서 말한 "담당자의 확인사항" 세 가지 순서로 그 대응 계획을 세웁니다.

- **첫째, 영향받는 주문.** 답변의 출처를 눌러 객체 탐색으로 넘어가, 한결모터스 → 수주 → 작업지시 → 공정 → P103까지 연결을 직접 따라갑니다.
- **둘째, 대체 설비.** 탐색으로는 "무엇이 멈췄는지"까지만 보입니다. 같은 대화로 돌아와 AI에게 대체 설비를 비교시킵니다.
- **셋째, 작업 이동 계획.** 재배정 계획을 저장하고 목록에서 확인합니다. "실제 수정은 원천 담당자가 한다"로 맺습니다.

| 부 | 목표 시간 | 화면 | 하는 일 |
| --- | --- | --- | --- |
| 시작 | 0:00~0:10 | AI 업무 도우미 | 영상의 대화로 잇기 |
| 1부 | 0:10~0:30 | AI 업무 도우미 | 영상의 답 → 출처에서 객체 탐색으로 |
| 2부 | 0:30~2:10 | 업무 데이터 > 객체 탐색 | 한결모터스에서 P103까지 따라가기 |

### 시작 전 화면 상태

- 관리자 계정으로 로그인, 탭 하나, 브라우저 확대 110~125%
- 영상의 질문 하나만 들어 있는 대화를 새로 만들어 둠: `한결모터스 11월 4일 납기건 진행사항에 대해서 상세하게 알려줘`
  - 답에 영상과 같은 줄이 있는지 확인: `20공정: 중단, 잔량 3,200개, P103` · `30공정: 중단, 잔량 3,200개, P103`. 같은 질문도 답이 조금씩 달라지므로, 없으면 대화를 지우고 다시 만듦
  - 질문 A·B까지 보낸 대화는 시작 대화로 쓸 수 없음
- 이 대화가 왼쪽 `대화` 목록 **맨 위**에 있고, 대화창 맨 위 제목 줄에 영상의 질문이 보임(상단 메뉴 `AI 업무 도우미`는 목록 맨 위 대화를 엶)

- 입력란 위 `내 질문`에 질문 A·B가 저장돼 있음. 저장은 그 브라우저에만 남으므로 발표에 쓸 PC·브라우저에서 미리 저장함(입력란에 질문을 넣고 ☆). 버튼에는 앞 16글자만 보임

## 4.10 시연 뒤 정리

- `s5_fix.sql`을 적용했다면 다음 시연 전에 원천 ERP를 `data-v1.0` 상태로 되돌립니다(`erp.item`의 BRK-990T와 `erp.change_log`의 71번 행 삭제, 또는 원천 재적재 후 다시 읽기).
- 시연 중 만든 재배정 계획과 대화는 플랫폼 DB에만 남고 원천에는 영향이 없습니다. 대화는 `AI 업무 도우미` 왼쪽 목록의 `삭제`로 지웁니다. 재배정 계획은 화면에서 지울 수 없습니다.
- 시연에서 승인한 후보(`금형 → 품목` 등)를 다시 검토하려면 현재 상태에서 재분석하고 새 후보·기존 규칙과의 차이를 검토합니다. 첨부 [스키마·초기 데이터 덤프](3-db-dump/README.md)는 시연 직전 상태의 백업이 아니므로 이를 복원하면 연결·객체·후보·계획은 돌아오지 않습니다. 초기 상태부터 다시 만들 때는 빈 별도 환경에 복원하고 4.0의 준비 절차를 반복합니다. 기존 환경을 시점 복원하는 작업은 현재 데이터 백업과 별도 복구 계획으로 진행합니다.
