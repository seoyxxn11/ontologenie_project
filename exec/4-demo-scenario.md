# 4. 시연 시나리오

프레스 공정 공장의 ERP·MES 원천 데이터(팀이 만든 합성 데이터, 기준 시각 2026-10-30 14:00)를 연결해, AI 제안으로 온톨로지를 만들고 Agent로 설비 고장에 대응하는 흐름입니다. 시나리오 번호는 [README](../README.md) 2절(S1~S7)과 같습니다.

화면 이름·버튼 이름·위치는 2026-11-16 운영 서버(`https://ontologenie.com`) 관리자 화면에서 확인한 그대로입니다. 위치는 PC 브라우저(가로 1440px 안팎) 기준입니다.

## 4.0 시연 전 준비

| 항목 | 확인 |
| --- | --- |
| 서비스 주소 | `https://ontologenie.com` (Chrome 권장) |
| 계정 | 관리자 1개(ADMIN). 민감 값 열람을 보여 줄 때만 생산기획자(PLANNER) 계정을 따로 만듭니다(4.7). 비밀번호는 팀이 보관 |
| 원천 | ERP·MES 원천 서버가 켜져 있고, 데이터 연결 화면에서 두 원천이 모두 `수집 접속 확인됨` |
| 수집 | Kafka Connect 커넥터 2개가 RUNNING, batch의 CDC 소비자가 켜져 있음 |
| LLM | GMS 키가 유효하고 크레딧이 남아 있음(AI 분석·Agent 모두 사용) |
| 시연 데이터 | 원천이 `ai/data/data-v1.0` 상태. 전에 CDC 시연을 했다면 `ai/data/scenario-v1.0/cdc_99_restore.sql`로 되돌림. S5에서 쓸 `s5_fix.sql`은 아직 적용하지 않음 |
| 분석 상태 | 운영 서버에는 AI 분석이 이미 끝나 있어, 연결 규칙 화면에 `검토 대기` 후보가 남아 있습니다(11-16 기준 전체 132, 검토 대기 63). 4.3의 `금형 → 품목`, `작업지시 → 수주 상세` 후보는 S2·S5 시연용으로 `검토 대기`로 남겨 둡니다 |

## 4.1 화면 배치

모든 화면이 같은 틀을 씁니다.

```
┌───────────────────────────────────────────────────────────────────────────┐
│ ONTOLOGENIE(로고)     업무 데이터 │ AI 업무 도우미 │ 데이터 연결 │ 연결 규칙 │ Action 정의  [⚙] │
├──────────────┬────────────────────────────────────────────────────────────┤
│ 운영·관리 패널 │                                                            │
│ (⚙를 누르면   │                       화면 본문                             │
│  왼쪽에 열림) │                                                            │
│ 실행 이력     │                                                            │
│ 객체 유형     │                                                            │
│ 정합성 검사   │                                                            │
│ 정의·규칙 이력│                                                            │
│ 계정·권한     │                                                            │
│ ───────────  │                                                            │
│ 관리자        │                                                            │
│ [로그아웃]    │                                                            │
└──────────────┴────────────────────────────────────────────────────────────┘
```

- **상단 메뉴**(오른쪽 위): `업무 데이터`(`/explorer`), `AI 업무 도우미`(`/agent`), `데이터 연결`(`/admin/sources`), `연결 규칙`(`/admin/rules`), `Action 정의`(`/admin/actions`). 관리자가 아니면 뒤의 세 메뉴가 보이지 않습니다.
- **톱니(⚙) 버튼**(상단 맨 오른쪽): 누르면 왼쪽에 `운영·관리` 패널이 열립니다. `실행 이력`(`/audit`), `객체 유형`, `정합성 검사`, `정의·규칙 이력`, `계정·권한`과 맨 아래 `로그아웃`. 패널은 오른쪽 위 `×`로 닫습니다. 관리자가 아니면 패널 제목이 `내 메뉴`이고 관리 항목이 빠집니다.

| 2 | 같은 화면, 상세 카드 아래 탭 | `접속 정보` 탭(기본) → 오른쪽 `연결 다시 확인` 버튼 | 아래 `연결 확인 결과`: 수집 계정·AI 분석 계정 접속 확인됨. `▶ 계정별 상세`를 펼치면 계정별 결과. 원천에는 쓰지 않음 |

| 5 | 같은 화면 | 오른쪽 위 보라색 `AI 관계 제안 받기` | `분석 대상 선택` 창이 열림. 왼쪽 위 `등록된 원천` 드롭다운(ERP 운영 DB · 14개 자료), 왼쪽 `테이블·자료 찾기` 목록, 오른쪽 컬럼 선택 |
| 6 | `분석 대상 선택` 창 | 왼쪽 목록에서 표를 골라 오른쪽에서 컬럼 체크 → `등록된 원천`을 `MES 운영 DB`로 바꿔 같은 방식으로 선택 → 창 아래 오른쪽 `분석하고 후보 받기` | 창 아래 왼쪽에 `n개 원천 · n개 테이블 · n개 컬럼 · n개 문서·자료` 요약. 읽기 권한이 없는 표는 고를 때 빨간 안내가 나옴. 실행하면 연결 규칙 화면으로 가서 분석 진행 상태를 보여 줌 |
| 7 | 상단 `연결 규칙` | 위쪽 탭 `전체`·`검토 대기`·`보류`·`승인`·`거절` 숫자 확인 | AI가 만든 객체 유형·속성·관계·연결 규칙 후보. 시간이 부족하면 5~6은 창만 열어 보여 주고 오른쪽 위 `닫기`로 닫은 뒤, 이미 끝난 분석 결과로 넘어갑니다 |

## 4.4 제안 검토와 온톨로지 적용 (S2)

연결 규칙 화면은 위에서부터 ① `AI 관계 제안 받기`(왼쪽)·`수동 검사·실행 목록`·`직접 관계 제안`(오른쪽) ② 상태 탭과 맨 오른쪽 `적용 후 문제` ③ `객체 속성`·`매핑` 전환 버튼과 `후보 검색` 칸, `검색 적용`·`초기화` ④ 왼쪽 후보 목록과 오른쪽 후보 상세 순서입니다.

| 순서 | 화면 | 클릭·입력 | 보여 줄 것 |
| --- | --- | --- | --- |
| 1 | `연결 규칙` | `객체 속성` 버튼(기본) → 왼쪽 목록에서 `현장 작업자` 클릭 | 오른쪽 상세: `연결·변환 규칙` 표(원천 컬럼 → 값 처리 → 저장할 속성), `제안 근거`(신뢰도, 분석 실행 번호, 제안 이유, AI 의견, 원천 근거 `MES_MAIN · mes.worker`) |
| 2 | 같은 화면 | `매핑` 버튼 → `후보 검색`에 `sales_order` 입력 → `검색 적용` → 왼쪽 목록 맨 위 `작업지시 → 수주 상세 (주문 참조 번호·생산 제품 코드)` 클릭 | 조건 2개(`WORK_ORDER.so_ref` 숫자 추출 = `SALES_ORDER_LINE.so_no` 숫자 추출, 제품 코드 같음). 제안 이유에 "작업지시 136행 중 134행(98%)" 연결. 목록에 노란 `보류 권고` 표시 |
| 3 | 같은 후보, 상세 중간 | `최근 정합성 검사` 카드 확인 → `검사 상세·표본 보기` | 승인 전 후보 시험 결과(전체·정상·미연결·중복·조건 위반 건수, 시험 매칭률). 연결되지 않은 원천 키 표본 |
| 4 | 같은 후보, 상세 맨 아래 `검토 결정` | `검토 사유 (필수)`에 사유 입력 → `승인`(또는 `이 후보 보류`, `거절`) | 사유 없이는 버튼이 눌리지 않음. 승인하면 정의·매핑 반영과 원천 다시 읽기가 시작되고 결정 이력이 남음. AI 신뢰도만으로 승인하지 않고 같은 개정의 검사 결과를 서버가 다시 확인 |
| 5 | 같은 화면 (선택) | `검토 대기` 상태의 연결 규칙 후보에서 제목 오른쪽 `규칙 후보 수정` → 관계·속성을 이름으로 검색해 조건을 고친 뒤 저장 | 새 개정으로 저장되고 다시 시험 적용. 제목 오른쪽 `이력`에서 개정 전후 비교 |
| 6 | ⚙ → `객체 유형` | 왼쪽 표에서 `설비` 클릭 | 오른쪽 `유형 설정`: `대표 속성` 드롭다운(설비 이름) + `대표 속성 저장`, `조회 그룹` 드롭다운(`비공개 (그룹 없음)`·`생산·설비 (PRODUCTION)`·`영업·구매·재고 (SALES_SUPPLY)`) + `그룹 저장`. 그룹이 없으면 어느 역할에도 이 유형이 보이지 않음. `▶ 원천 데이터 정책`을 펼치면 금지·제한 컬럼 |
| 7 | ⚙ → `정의·규칙 이력` | 위 `정의 변경` 탭(기본)·`규칙 개정` 탭, `시작일`·`종료일`·`대상`으로 `검색` → 행의 `▶ 내용 보기` | 누가 언제 무엇을 바꿨는지 전후 기록 |

## 4.5 정합성 문제와 재검증 (S5)

예시는 MES 금형 `MD-990T-01`의 생산 제품 코드 `BRK-990T`가 ERP 품목 마스터에 없는 문제(검사 K4)입니다.

| 순서 | 화면 | 클릭·입력 | 보여 줄 것 |
| --- | --- | --- | --- |
| 1 | `연결 규칙` | `매핑` → `후보 검색`에 `mes.die` → `검색 적용` → 왼쪽 `금형 → 품목 (생산 제품 코드)` | 제안 이유 "금형 6행 중 5행(83%)… 이어지지 않은 값 예: BRK-990T". `최근 정합성 검사`: 정상 5, 미연결 1, 시험 매칭률 83.3% |
| 2 | 같은 후보, `검토 결정` | 사유 입력 → `승인` | 규칙이 반영되고, 다음 자동 검사(운영 서버 목록 기준 5분 간격)부터 미연결 행이 문제로 잡힘 |
| 3 | 같은 화면, 상태 탭 맨 오른쪽 | `적용 후 문제 · 전체 n건 (해결 포함)` 클릭 | `적용 후 문제` 표: 문제·행, 관련 규칙, 상태(`신규`·`확인중`·`조치완료·재검증대기`·`해결`), 실패 이유. 위쪽 상태 버튼으로 거름 |
| 4 | 같은 표 | BRK-990T 문제의 왼쪽 `#번호 · 미연결` 링크 | `적용 후 문제 상세` 창: `원천 근거`(원천 키·값), `원천 전달 기록`, `상태 변경 이력`, `처리 상태 변경`, `재검증`. 원천 측에 전달할 내용을 보여 주며 플랫폼은 원천을 고치지 않음 |
| 5 | 상세 창 `처리 상태 변경` | 바꿀 상태 `확인중` 선택 → `변경 사유` 입력 → `상태 변경` | 상태가 `확인중`으로 바뀌고 이력이 남음 |
| 6 | (원천 담당 역할) | 원천 ERP에 `ai/data/scenario-v1.0/s5_fix.sql` 적용(`erp.item`에 BRK-990T 추가) | 원천 수정이 CDC로 들어옴. 데이터 연결 화면의 `CDC 마지막 반영` 시각이 바뀜 |
| 7 | 상세 창 | `처리 상태 변경`에서 `조치완료·재검증대기`로 변경 → `재검증` 영역의 `재검증 실행` | `재검증 실행 #n을 접수했습니다.` → 실행 상태가 완료되면 이번 재검증 검사 결과에서 문제가 해소됨 |
| 8 | 상세 창 | `처리 상태 변경`에서 `해결` 선택 → `통과한 재검증 실행 ID`에 7의 번호 입력 → `상태 변경` | 재검증을 통과해야만 `해결`로 바꿀 수 있음 |
| 9 | ⚙ → `정합성 검사` | 왼쪽 `검사 실행 목록`에서 실행 클릭(위 `검사 종류` 드롭다운으로 `문제 재검증`만 거를 수 있음) | 오른쪽 `검사 실행 #n`: 접수·시작·종료 시각, `규칙별 판정 집계`(전체·정상·미연결·중복·조건 위반). 오른쪽 위 `수동 검사 실행`으로 직접 검사도 가능 |

## 4.6 객체 탐색과 Agent 업무 조회 (S3)

| 순서 | 화면 | 클릭·입력 | 보여 줄 것 |

| 1 | 상단 `업무 데이터` | 위쪽 `ID · 이름 검색` 칸에 `P103` → 오른쪽 보라색 `검색`(또는 왼쪽 `객체 목록`에서 `P103 1라인 3호 프레스` 클릭) | 가운데가 `1라인 3호 프레스와 연결된 정보` 관계도로 바뀜. 가운데 `설비 · P103`을 둘러싸고 공정 실적 198건, 설비 센서 측정 153건, 불량 기록 122건, 작업지시 공정 배정 122건, 설비 비가동 기록 10건, 정비 지시 4건(연결된 정보 609건). ERP·MES 데이터가 한 객체로 묶임 |

| 3 | 같은 화면, 가운데 관계도 | 왼쪽 아래 `설비 비가동 기록 10건` 상자 클릭 | 왼쪽 목록이 `설비 비가동 기록 10건`으로 바뀜(각 행에 연결 원천 행 `downtime_id`). 행을 누르면 비가동 DT-0460(10-30 03:10 시작) 같은 상세. `정비 지시 4건`에서는 RP-26-041 진행 중. 목록 위 `← 검색 결과`, 관계도 오른쪽 위 `← 전체 구조로`로 돌아감 |
| 4 | 같은 화면 | 오른쪽 `상세 정보`의 보라색 `AI에 질문` | 새 대화가 만들어지며 AI 업무 도우미로 이동하고, 입력 칸에 "1라인 3호 프레스에 연결된 업무 정보를 알려줘"가 미리 채워짐 |
| 5 | 상단 `AI 업무 도우미` | 왼쪽 `대화` 목록 오른쪽 위 `+`(새 대화) → 아래 입력 칸 `업무에 대해 질문해 주세요.`에 "지금 정지 중인 설비 있어?" → 오른쪽 `↑`(보내기) | P103(정비중). 답변 아래 `▶ 출처 및 조회 상태`를 펼치면 출처 객체(`#번호 열기 ↗`로 업무 데이터 화면 이동)와 기준 시점 |
| 6 | 같은 대화 | "P103 진동이 언제부터 상한을 넘었어?" | 2026-10-28 09:00(4.90 > 상한 4.50) |
| 7 | 같은 대화 | "P103에서 중단된 JB2610-0141의 공정과 잔량을 확인하고, 연결된 수주와 납기를 알려줘." | 공정 20·30, 잔량 3,200, 수주 OD-2610-021(납기 2026-11-04) |
| 8 | 같은 대화 | "P103의 최근 비가동 이력과 ERP 장부가 알려줘" | 비가동 이력은 답하고, 장부가(고정자산)는 원천에서 들이지 않는 데이터라 지어내지 않고 "볼 수 없음"으로 답함 |

입력 칸 오른쪽 별(☆) 버튼은 `내 질문 저장`입니다. 자주 쓰는 질문을 브라우저에 저장해 두면 입력 칸 위 `내 질문`에서 한 번에 다시 보낼 수 있습니다.

## 4.9 시연 뒤 정리

- `s5_fix.sql`을 적용했다면 다음 시연 전에 원천 ERP를 `data-v1.0` 상태로 되돌립니다(`erp.item`의 BRK-990T와 `erp.change_log`의 71번 행 삭제, 또는 원천 재적재 후 다시 읽기).
- 시연 중 만든 재배정 계획과 대화는 플랫폼 DB에만 남고 원천에는 영향이 없습니다. 대화는 `AI 업무 도우미` 왼쪽 목록의 `삭제`로 지웁니다.
- 시연에서 승인한 후보(`금형 → 품목` 등)를 다시 시연하려면 플랫폼 DB를 덤프([3-db-dump](3-db-dump/README.md))로 되돌리거나 분석을 다시 실행합니다.
