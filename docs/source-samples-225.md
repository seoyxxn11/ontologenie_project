# S15P31C106-225 원천 표본 화면

데이터 연결 → 원천 선택 → 원천 표본 탭 (`/admin/sources?source={id}&tab=samples`).
읽기 가능한 TABLE 선택, 행 수 1~20(기본 20), 요청 접수·대기·실행·실패·성공,
빈 결과, 만료·404, 기존 요청 합류를 지원한다.

## 현재 연결 범위

- 409에서 `sampleApi.ts`의 016·102 어댑터를 `SourcesPage`의 PostgreSQL 원천에 주입했다. 표본 조회는 사용자가 명시적으로 요청할 때만 접수한다.
- `samplePreview.ts`는 화면 전용 모델이다. 실제 요청 경로·응답 검증과 화면의 비동기 흐름은 합성 데이터 기반 테스트로 확인한다. 운영 원천 데이터로 접수한 결과는 별도 검증 대상이다.
- 표본은 컴포넌트 수명 동안만 보관하며 React Query 캐시·브라우저 저장소에 넣지 않는다. 대상 전환·만료 시 제거한다. 원천 오류 원문은 표시하지 않는다.

## 016·102 연동 계약

- [016 원천 행 표본 조회](https://app.notion.com/p/405bdf14d2d881c38992f8d890695803) — ADMIN이 `POST /api/v1/sources/{id}/resources/{resourceId}/samples`로 요청한다. `rowLimit`은 1~20이고 기본은 20이다. 202 응답의 `previewId`로 결과를 조회한다. 동일한 진행 중 요청에 합류하면 `joined=true`를 받는다.
- [102 원천 미리보기 결과 조회](https://app.notion.com/p/406bdf14d2d8817fa984ccd997fb1d8b) — `GET /api/v1/ontology/source-previews/{previewId}`로 완료 또는 실패까지 상태를 조회한다. `SAMPLE` 성공 결과의 `columns[]`와 `rows[][]`는 같은 순서다. 요청 후 1시간이 지나거나 결과가 삭제되면 404다.

## 표본에 표시할 컬럼과 값

2026-11-14 코드에서 391의 `SourceColumnPolicy` 적용을 확인했다. 정책의 원본과 등급 목록은 [원천 데이터 정책](data-access.md#원천-데이터-정책-391)이다. 프론트가 별도 분류 목록을 만들지 않는다.

- 016 배치는 수집 계정의 원천 읽기 권한을 적용한다. 금지 표는 읽지 않고 실패하며, 금지·민감 컬럼은 원천을 읽기 전에 제외한다. 이 서버 로직과 정책 파일은 409에서 변경하지 않았다.
- 화면은 102 응답의 `columns`와 `rows`를 기준으로 표를 그린다. 제외한 컬럼의 헤더와 셀은 응답에 없으므로 화면에도 나타나지 않는다. 응답에 있는 실제 `null` 값은 `NULL`로 표시한다.
- `erp.employee.emp_no`(사번)는 원천 읽기 권한이 있으면 표시한다. `erp.vendor.biz_no`(사업자등록번호)는 읽기 권한이 있으면 원천에서 뒷자리를 가린 값을 그대로 표시한다.

## 409의 화면 연동

1. 016 접수의 `previewId`·상태·합류·만료 정보와 102의 SAMPLE 종류·대상 테이블·상태·컬럼/행 구조를 검증한다. 다른 대상·매핑 미리보기·잘못된 응답을 표본으로 표시하지 않는다.
2. 대기·실행·성공·실패, 빈 결과, `joined`, 만료·404, 권한 오류를 표시한다. 조회 실패를 재시도할 때는 상태 조회만 다시 실행한다.
3. 응답의 컬럼 순서·값과 기존 가림을 유지한다. 화면·쿼리 캐시·브라우저 저장소에서 제외 컬럼의 원문을 복원하거나 추가 조회하지 않는다. 원천 오류 원문은 전달하지 않는다.
4. 실제 서버 정책 테스트와 화면 어댑터 테스트를 구분해 검증한다. 운영 배포·운영 원천 데이터 조회 확인은 별도다.
