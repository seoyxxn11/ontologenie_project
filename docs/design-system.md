# OntoloGenie UI/UX 디자인 시스템

제조 업무 데이터를 빠르게 찾고, 비교하고, 판단하기 위한 현재 공통 기준이다. 제품 맥락은 [PRODUCT.md](../PRODUCT.md)를 따른다.

## 0. 문서 사용법

- 이 문서는 승인된 원칙·규격·공통 동작을 정의한다. 기준이 적혀 있다는 사실이 모든 화면의 구현·검증 완료를 뜻하지 않는다.
- 문서의 토큰 이름은 의미 이름이다. 실제 CSS 이름은 기존 `--ui-*`와 공통 컴포넌트를 우선 사용한다. 변수·클래스의 일반적인 이름은 기존 컨벤션에 따라 작성하고, 새로운 시각 규격·업무 동작은 사용자 결정을 받는다.
- `draft`는 세부 명세와 수용 검토가 남아 있음을 뜻한다. 이미 승인된 아래 기준을 미결정으로 되돌리지 않는다. 코드·팀 문서와 충돌하면 차이를 보고한다.

## 1. 제품·시각 원칙

- 라이트 테마와 보라색 키컬러 `#8975F6`를 유지한다. 페이지 전체 바탕은 불투명한 흰색이며, 회색은 영역·상태를 구분할 때 국소적으로 사용한다.
- 가독성과 기본형 밀도를 우선한다. 관련 정보는 가까이 묶고, 반복 카드·장식·큰 여백으로 핵심 정보를 밀어내지 않는다. 별도 밀집 모드나 다크 테마를 추가하지 않는다.
- 상세 조회는 우측 패널이 기본이며 복잡한 편집은 별도 페이지로 구성한다. 데스크톱 업무를 중심으로 한다.
- AI 답변·조회 결과에 출처와 기준 시점을 제공한다. 근거·진행률·성과·확신을 만들어 표시하지 않는다.
- 제안·검토·승인·반영·검사·실행을 구분한다. AI 신뢰도를 승인·반영 성공처럼 표현하지 않는다.
- 원천 시스템은 읽기만 한다. 플랫폼의 계획 생성·저장을 원천 ERP·MES 수정처럼 표현하지 않는다.
- 문구는 검색·저장·승인처럼 구체적인 동사를 쓰고, 오류는 상황 → 사유 → 다음 행동 순서로 설명한다. 업무 용어는 기존 기능 명세의 의미를 따른다.

## 2. 정보 구조와 읽기 흐름

- 목록은 식별 정보와 비교할 핵심 값·상태를 우선한다. 상세는 이름·ID·주요 행동 → 기본 정보 → 관계·근거·이력으로 구성하되 실제 업무 순서에 맞춘다.
- 필수 경고·차단 사유는 접힌 영역에만 숨기지 않는다. 긴 설명·전체 속성·이력은 이름 있는 섹션으로 제공한다.
- 공통 업무 페이지의 `PageHeader variant="page"`는 스크린리더용 `h1`을 유지하고 짧은 설명은 렌더링하지 않는다. 주요 행동은 별도 상단 영역에 둔다. 현재 위치는 탐색 선택 상태로 구분한다.
- `variant="message"`와 로그인은 제목을 표시한다. 개별 화면의 독립 제목을 일괄 숨기지 않는다.
- 같은 역할에서 메뉴 위치·명칭·발견 가능성을 통일한다. 결과 수는 한 곳을 기본으로 하며 중복 표시 시 값·용어를 일치시킨다.
- 고정 헤더·작업 바·내부 스크롤이 내용과 키보드 포커스를 가리지 않게 한다. 읽기 어려울 때는 패널 재배치·전환·확장을 사용하고 글자 축소나 일괄 말줄임으로 해결하지 않는다.
- 로그인은 로고·제목·계정 ID·비밀번호·로그인 버튼과 반응형 오브를 표시하며 WELCOME·소개 문구는 두지 않는다.

데이터 연결은 사용자 승인 시안에 따라 상단의 원천 이름·접속 상태 선택 버튼과 전체 너비 상세를 사용한다. 원천은 서버 목록 전체에서 선택하며 ERP·MES로 하드코딩하지 않는다. 선택은 보라 보조 면·테두리·밑선과 aria-pressed로 구분하고, 버튼·포커스는 공통 규격을 따른다. 원천이 많으면 선택 영역에서 줄바꿈·제한된 내부 스크롤로 접근하며 상세를 불필요하게 아래로 밀지 않는다.

기본 원천 버튼은 같은 최소 폭을 유지하되 긴 이름은 가용 폭에서 원문 전체를 줄바꿈한다. 좁은 화면의 긴 이름은 한 행을 사용한다. 선택 영역은 적어도 버튼 하나를 온전히 보여줄 높이를 허용하며, 이름 하나 때문에 같은 줄의 다른 버튼 높이를 늘리지 않는다. 수집·계정 검사 상태 전환은 지속되는 polite/atomic 상태 영역으로 전달하고 오류의 즉시 안내를 유지한다.

원천 등록은 상단 왼쪽의 원천 선택 버튼 옆에 보조 버튼으로 둔다. 여러 원천을 대상으로 하는 ‘AI 관계 제안 받기’는 개별 원천 상세 밖의 상단 오른쪽에 주요 버튼으로 두어 작업 범위를 구분한다. 좁은 화면에서는 같은 읽기 순서로 줄바꿈하며 기존 분석 대상 선택 흐름을 유지한다.

이 화면의 상태 요약은 접속 확인·최근 전체 읽기·CDC 마지막 반영 시각을 항상 표시한다. 설명만 ‘상태·시각 기준’에서 펼치고 실패·권한 제한·조회 불가와 재시도·수집 이력 경로는 기본 노출한다. 접속과 수집 성공을 구분하며 CDC 시각을 현재 정상 여부나 반영 지연으로 표현하지 않는다. 상세 제목은 기존 24px/36px·700, 일반 섹션은 16px/24px·600이며 원천 등록·수정·5개 상세 탭·AI 관계 제안 흐름은 유지한다.

CDC 시각과 기준 설명은 상단 요약에서만 제공하고 수집 이력 탭에 반복하지 않는다. 데이터 연결의 상태 요약은 공통 상태 배지 표시의 화면별 예외로, 항목/값 2열 구조를 사용한다. 두 시각은 같은 값 시작선에 맞추고, 최근 전체 읽기의 완료 상태는 날짜 뒤에 작은 텍스트(12px/18px)로 표시한다. 좁은 화면에서는 날짜와 완료 표시의 줄바꿈을 허용하며, 여러 줄인 값의 항목명은 값 첫 줄에 맞춘다. 접속 상태와 대기·실행 중·실패·조회 불가도 텍스트로 구분한다. 다른 화면의 공통 배지 규격은 유지한다. 완료 시각 앞에 같은 상태 문구를 반복하지 않고 실패 종료와 성공 완료 시각의 의미를 계속 구분한다.

원천의 접속 상태 표시는 수집 계정 기준임을 문구에 명시하며 AI 접속 성공으로 확대하지 않는다. 정상 계정 검사 결과는 확인된 용도만 한 줄로 요약하고 계정명·표·컬럼 수는 ‘계정별 상세’에 모은다. 실패·조회 오류·시간 초과는 접힌 상세 밖에 표시하며 검사 작업이 완료됐어도 AI 계정만 실패했다면 해당 사유를 기본 노출한다. 계정 설정·검사·수정 기능은 유지한다.

## 3. 공통 동작과 데이터 표시

### 검색과 상세 선택

| 상황                       | 기준                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------- |
| 텍스트·복합 조건 입력      | 버튼 또는 Enter로 적용. 입력 중에는 기존 결과·페이지·상세 선택 유지                         |
| 기존 즉시 적용 단일 필터   | 동작 유지, 사용처·이유를 예외로 기록. 입력 중인 다른 검색 조건을 함께 제출하지 않음         |
| 다른 조건 적용             | 첫 페이지로 이동하고 이전 상세 선택 해제                                                    |
| 같은 조건 재조회·목록 갱신 | 적용 조건·같은 ID의 상세 선택 유지. 목록에서 보이지 않는다는 이유로 삭제를 단정하지 않음    |
| 초기화                     | 해당 검색 영역의 조건 초기화                                                                |
| 브라우저 재로드            | 기존 URL 객체 ID 복원 유지. 검색 조건·페이지 복원은 이번 공통 지원 범위에 추가하지 않음     |
| 삭제·권한 상실 확인        | 이전 상세를 제거하고 실제 응답에 맞는 사유 안내. 통신 실패를 삭제·권한 상실로 단정하지 않음 |

### 폼·Dialog·실행 추적

| 상황                    | 기준                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 입력                    | label → 입력 → 도움말/오류 순서. 필수 여부 표시, placeholder로 label 대체 금지                                                            |
| 입력 오류               | 오류 경계색＋입력 아래 문구＋`aria-invalid`·설명 연결. 오류 아이콘은 필수 아님                                                            |
| 조회 전용 Dialog        | 닫기 버튼·Escape·배경 클릭 닫기 유지                                                                                                      |
| 전송 전 미저장 폼       | 배경 클릭 닫기 차단. 닫기·Escape·취소·메뉴 이동·뒤로 가기는 폐기 확인. 편집 계속 시 입력 유지                                             |
| 브라우저 재로드·탭 닫기 | 브라우저가 허용하는 기본 이탈 경고 제공. 경고 노출·문구를 항상 보장하지 않음                                                              |
| 전송 후 저장·실행 중    | 전송 전 폐기 확인보다 우선. 중복 제출 방지, 처리 계속 안내와 진행·결과 재확인 경로 제공. 닫기를 요청 취소나 변경사항 폐기로 표현하지 않음 |
| 저장 실패·성공          | 실패는 입력·지속 오류·다음 행동 유지. 성공한 저장분은 미저장 변경으로 취급하지 않음. 로그인은 제출 종료 시 비밀번호 초기화 예외 유지      |
| 장시간 실행·위험 행동   | 대상·영향·진행·결과를 표시. 실제 취소 기능이 없으면 취소 가능 문구 금지. 중첩 Dialog는 기본적으로 피함                                    |

Dialog는 열릴 때 포커스 이동, 내부 Tab 순환, 닫힌 뒤 호출 위치 복귀를 제공한다. 폐기 확인은 기존 창 안의 단계로 구성할 수 있으며, 편집 복귀 시 입력과 포커스를 보존한다. 비활성 입력에는 사용자 언어의 사유·대체 경로를 제공하고 내부 구현 상황을 노출하지 않는다.

### 값·시각·피드백

- 미제공은 `—`, 실제 0은 `0`으로 구분한다. 미제공·알 수 없음·조회 실패의 의미를 섞지 않는다.
- 날짜는 `YYYY-MM-DD`, 시각은 `Asia/Seoul` 고정의 `YYYY-MM-DD HH:mm:ss KST`로 표시한다. 날짜 전용 값의 업무 의미를 시간대 변환으로 바꾸지 않는다. API의 ISO 8601 저장·전송 형식과 화면 표시 형식을 구분한다.
- 이름·상태·날짜는 좌측, 수량은 우측 정렬한다. 수량·시각 비교에 `tabular-nums`를 사용한다. ID를 숫자 형식으로 바꾸거나 도메인 명세 없이 반올림하지 않는다.
- 긴 값은 줄바꿈·원문 확인·명시적 복사 경로를 제공하고 hover에만 숨기지 않는다.
- 검색 전·데이터 없음·조건 결과 없음·조회 실패를 구분한다. 이전 결과를 유지하며 조회할 때는 갱신 중임을 표시한다.
- 저장 성공은 짧은 비차단 안내와 갱신 상태, 실패·승인 요청·장시간 결과는 지속 안내로 제공한다. 필수 내용을 토스트만으로 전달하지 않는다.
- 조회 재시도와 저장·실행 재요청을 구분한다. 상태 불명확한 실행을 실패로 단정하거나 자동 재실행하지 않는다.

## 4. 색상과 상태

### 기본 색상

| 의미 이름                       | 값                       | 용도                            |
| ------------------------------- | ------------------------ | ------------------------------- |
| brand-primary                   | `#8975F6`                | 선택·진행·포커스                |
| brand-strong / brand-text-light | `#6F5ADF`                | 주요 버튼 면·작은 활성 링크     |
| brand-subtle                    | `rgb(137 117 246 / 10%)` | 선택 보조 면                    |
| on-brand                        | `#FFFFFF`                | brand-strong 위 글자            |
| on-brand-primary                | `#121212`                | brand-primary 위 작은 글자      |
| background-1                    | `#FFFFFF`                | 전체 바탕·패널·표·Dialog        |
| background-2                    | `#F7F7F7`                | 헤더·관계도·비활성 등 국소 면   |
| background-3 / background-4     | `#EEEEEE` / `#E2E2E2`    | hover·보조 구분 면              |
| foreground-1 / foreground-2     | `#121212` / `#505050`    | 본문·제목 / 보조 문구·메타 정보 |
| border-1 / border-2             | `#EEEEEE` / `#E2E2E2`    | 일반 / 강조 구분선              |
| 입력 경계                       | `#8A8A8A`                | 입력의 조작 경계                |

일반 보조 문구도 foreground-2를 사용한다. `#8A8A8A`·`#D0D0D0`는 일반 글자에 사용하지 않으며 비활성 컨트롤·순수 장식에 한정한다. 읽어야 하는 비활성 사유는 예외로 처리하지 않는다. 기존 보조 포인트 `#8065D8`를 작은 링크에 그대로 재사용하지 않는다.

페이지·패널은 흰 면과 여백·제목·구분선으로 먼저 나눈다. 전체 회색 바탕·장식 그라데이션·버튼 그라데이션을 사용하지 않는다. 선택은 색과 선·체크·테두리를 병행한다.

| 실제 완료·성공                       | `success`. 검토·승인·반영·검사·실행 중 무엇이 완료됐는지 명시                              |
| 실제 실패                            | `danger`와 실패 사유. 검토·승인 대기, 실행 대기, 차단을 실패로 단정하지 않음               |
| 차단                                 | 기본 `warning`과 차단 사유. 별도로 실제 실패가 발생했다면 해당 실패 상태는 `danger`로 구분 |
| 부분 완료                            | `warning`과 실제 제공된 완료·미완료 건수 및 사유. 건수가 없으면 만들지 않음                |
| 비활성·참고                          | `neutral`과 상태명. 단순 미선택을 오류로 표현하지 않음                                     |

Badge의 neutral·info·success·warning·danger와 기존 slate·blue·emerald·amber·red 계열을 유지한다. 업무 상태를 모두 보라색으로 바꾸거나 API 상태·권한을 변경하지 않는다. 상태명과 필요한 사유를 함께 제공한다.

### 대비

일반 글자 4.5:1, 큰 글자 3:1, 필요한 조작 경계·상태 표시 3:1을 목표로 한다. 작은 흰 글자는 brand-primary 대신 brand-strong 위에 사용한다. 실제 배경·반투명·hover·선택·포커스 조합으로 확인한다.

## 8. 페이지네이션

- 처음·이전·주변 번호·다음·마지막 구성, 현재 주변 번호 최대 5개. 경계에서는 범위를 이동한다. 전체가 5쪽 이하면 모두 표시한다.
- 첫 페이지는 처음·이전, 마지막은 다음·마지막을 비활성화하고 현재 번호 재조회는 막는다. 0건은 이동 컨트롤을 숨기고 0건 표시, 1쪽은 현재 번호와 비활성 이동 컨트롤을 둔다.
- 조회 중 중복 이동과 범위 보정을 미룬다. 조회 종료 후 마지막 페이지가 사라지면 마지막 유효 페이지로, 0건이면 0으로 부모 상태를 보정한다.
- 컨트롤 최소 40×40px·패딩 8px·radius 4px·간격 4px, 그룹과 건수 사이 8px·가운데 정렬. 현재 번호는 brand-primary＋on-brand-primary다.
- compact는 문구를 «·‹·›·»로 바꾸며 접근 가능한 이름을 유지한다. nav 이름은 페이지 이동, 현재 번호는 aria-current=page로 알린다. 좁은 창에서는 줄바꿈으로 조작을 유지한다.
- 전체 페이지 수는 Math.ceil(totalElements / size), size는 양수다. 새 페이지 크기 UI·URL 이동은 추가 요구가 있을 때 다룬다.

업무 데이터 화면은 사용자 승인 시안의 예외를 적용한다. 왼쪽 객체 목록은 페이지당 8개다. 관계도에서 관계명이나 유형 묶음을 선택하면 왼쪽을 해당 연결 객체 목록으로 전환하며, 가운데 아래에 같은 목록을 중복 표시하지 않는다. 연결 객체도 서버에서 8개씩 조회하고 전체 건수를 기준으로 이동한다. 기준 객체의 관계도를 유지한 채 오른쪽 상세를 바꾸며, 검색 결과 복귀와 선택 객체의 관계 탐색을 제공한다. 업무 데이터와 AI 업무 도우미 대화 목록의 페이지네이션은 높이 32px·최소 폭 28px(좁은 폭의 이동 버튼 24px)·간격 2px로 줄이고, 최대 5개 번호와 처음·이전·다음·마지막을 한 줄로 유지한다. 두 목록의 하단 건수·쪽수 요약은 생략하고 업무 데이터의 결과 수는 목록 제목 옆에서 확인한다. 대화 목록은 최소 행 높이 기준으로 페이지당 개수를 계산하고, 한 페이지가 가득 찼을 때만 표시 행이 가용 높이를 균등하게 채워 페이지네이션 위에 잔여 공간을 남기지 않는다. 대화 수가 적거나 마지막 페이지에 일부만 있으면 기본 행 높이를 유지하고 남는 공간은 둔다. 늘어난 표시 행 높이를 페이지 크기 계산에 다시 사용하지 않는다. 대화 목록은 기본 폭 288px·1000px 이하에서는 272px로 번호 5개를 위한 공간을 확보하며 기존 650px 이하 재배치를 유지한다. 다른 화면의 기본 규격과 근거 창의 전체 연결 조회는 유지한다.

검색 영역과 3열 패널 사이에는 32px 간격을 둔다. 3열에서는 목록 행이 가용 높이를 고르게 채우고 페이지네이션을 패널 하단에 붙인다. 검색 결과와 연결 객체 목록에 같은 기준을 적용하며 내부 스크롤은 추가하지 않는다. 좁은 창에서 열을 재배치할 때는 목록을 다른 두 패널의 합산 높이로 늘리지 않는다.

## 9. 관계도·비교·AI 표현

- 관계도의 객체명·유형명·관계명은 원문 확인이 가능해야 한다. 긴 이름은 노드 안에서 줄바꿈하고 공백 없는 문자열에는 overflow-wrap: anywhere를 사용한다.
- 개요·선택·포커스·연관 노드·연결선을 구분하고 범례를 제공한다. 확대·축소·맞춤·선택 해제의 위치·이름을 통일하며 목록·상세 선택을 연결한다. 필수 정보는 관계도에만 의존하지 않는다.
- 업무 데이터의 유형 관계도는 집중 보기·읽기 크기·전체 맞춤을 관계도 제목 줄 오른쪽에 두고, 왼쪽 아래에는 확대·축소·전체 화면 순으로 세로 배치한다. 전체 화면은 SVG 아이콘으로 표시하고 접근 가능한 이름과 툴팁을 제공하며, 진입 후에는 닫기 아이콘으로 전환한다. 별도 이전 보기 버튼과 상단 보기 상태 줄, 개요·유형 목록 전환과 관계도 확장은 생략한다. 유형 필터는 기존 검색 줄을 사용하며 객체 선택 후 전체 구조 복귀는 유지한다. 전체 화면에서는 세 보기 도구를 그림 안 오른쪽 위로 옮겨 접근을 유지한다. 읽기 크기는 선택한 유형이 없으면 현재 중심에서 1배로 맞춘다. 선택한 유형이 있으면 현재 배치를 유지하면서 그 유형과 직접 연결된 유형·연결선이 도구 모음을 피해 화면 안에 들어오도록 확대율과 중심을 조정한다. 연결 없는 선택 유형은 1배로 가운데에 놓는다. 읽기 크기는 유형을 숨기거나 집중 보기 상태를 바꾸지 않으며, 집중 보기에서도 현재 배치의 직접 연결 영역에 맞춘다. 전체 맞춤은 현재 표시된 유형과 연결선이 도구 모음을 피해서 캔버스 안에 들어오도록 조정한다. 집중 보기에서 전체 배치로 돌아갈 때와 전체 화면을 닫을 때는 기존 화면 위치를 복원한다. 방향 색상은 선택한 유형 기준으로 들어오는 관계는 황록, 나가는 관계·자기 관계는 보라로 구분한다. 범례는 현재 표시된 관계에 해당하는 항목만 보여 준다.
- 변경 전후는 같은 속성 순서로 비교하고 추가·수정·삭제를 색과 라벨로 구분한다. 검토·반영·검사 상태와 다음 행동을 신뢰도보다 먼저 보여 준다.
- AI 화면은 대화 목록·현재 대화·입력으로 나눈다. 목록 제목은 두 줄까지, 현재 대화 상단에서는 전체를 확인한다. 선택은 보라 보조 면과 왼쪽 선으로 표시한다.
- 질문·답변 본문과 질문 입력란은 공통 본문·입력 기준인 14px/21px로 통일한다. 마크다운 제목은 기존 제목 위계를 유지한다. 메시지 사이 간격은 16px, 답변 카드 상하 패딩은 12px·좌우 16px, 본문 문단 간격은 8px다. 출처·경고·실행 결과의 구분 간격은 유지한다. AI 업무 도우미는 사용자 승인 시안에 따라 답변·입력창을 현재 대화의 가용 폭에 맞추고, 이전 최대 880px 제한을 적용하지 않는다. 마크다운 구조를 구분하고 표·코드는 내부 스크롤로 읽는다. 출처·조회 상태는 14px 요약과 펼칠 수 있는 상세로 제공한다.
- 권한 제한·미확인·미연결·추정 건수는 실제 응답으로 계산해 접힌 요약에도 제공한다. 생성·근거 없음·실행 대기·처리·결과를 실제 상태로 구분한다.
- 대화 내역을 스크롤하고 입력란은 유지한다. 이전 답변을 읽는 중에는 새 응답으로 강제 하단 이동하지 않는다. 대화·표·코드에 키보드 접근을 제공한다.
- 질문 라벨·2,000자 입력 한도·Enter/Shift+Enter 안내를 유지한다. 사용자 승인에 따라 눈에 보이는 글자 수 카운터는 생략한다. 추천 질문·내 질문은 입력만 채우고 전송은 사용자가 결정한다. 전송 실패 시 입력·지속 오류를 유지한다.

- AI 업무 도우미의 바깥 여백은 1280px 이상에서 공통 40px를 따르고, 목록과 대화 사이 간격은 12px를 유지한다. 대화 영역은 헤더와 상하 바깥 여백을 제외한 가용 화면 높이에 맞춘다. 1280px 미만의 기존 화면별 여백·재배치는 유지한다. 상단은 14px/21px·500의 전체 대화 제목과 목록 접기·펼치기 버튼만 둔다. 접으면 답변과 입력창이 넓어지며 대화·질문은 유지한다.
- AI 대화 영역의 최소 높이는 480px이며, 높이 735px 이하의 데스크톱 창에서는 추천·내 질문 목록의 표시 높이를 한 행(40px)으로 줄이고 기존 내부 스크롤로 나머지 항목에 접근한다. 페이지 수가 세 자리 이상이면 대화 목록 페이지 버튼 글자를 12px·좌우 패딩 0으로 줄여 32px 높이·번호 5개·한 줄 배치를 유지한다. 650px 이하의 기존 세로 재배치는 유지한다.
- 새 대화 행동은 목록 제목 오른쪽의 + 아이콘이며 접근 가능한 이름과 hover·키보드 포커스 툴팁은 ‘새 대화’다. 아이콘은 20px·선 1.8, 클릭 영역은 40×40px다. 목록 제목과 + 아이콘은 보이는 윤곽 기준으로 양끝 약 16px 여백과 세로 중앙 정렬을 맞춘다. 대화별 미전송 질문은 화면을 사용하는 동안 보관하고 돌아오면 복원한다. 이미 새 대화에서 입력 중이면 +를 다시 눌러도 지우지 않는다. 브라우저 재로드 후 초안 복원은 지원 범위에 추가하지 않는다.
- 질문 입력창은 한 줄 높이(본문 40px·외곽 50px)로 시작하며 본문 입력 부분은 내용에 따라 40~160px로 자동 조정된다. 업무 질문 라벨은 접근성 이름으로 유지하고 시각적으로 생략한다. Enter/Shift+Enter 안내는 입력 영역에 포커스가 있을 때만 표시한다. 별 모양 저장과 위쪽 화살표 전송 버튼을 입력 경계 안 오른쪽 아래에 두며, 공통 40px 클릭 영역을 유지한다. 새 대화는 짧은 안내와 기존 추천 질문을 입력 가까이에 한 번만 표시한다. 메시지가 있거나 전송 중인 대화에서는 추천 질문을 숨기고 내 질문과 하단 입력창은 유지한다. 빈 상태·처리·실패·출처·실행 결과의 기존 의미와 행동은 유지한다.

### 연결 규칙 검토 배치

- 규칙 상세는 제목을 첫 줄에 두고 수정·이력 행동을 오른쪽에 묶는다. 식별 코드·개정·출처는 제목 아래, 검토·반영 상태는 같은 행에 정렬한다. 객체 속성 매핑 표는 원천 40%·값 처리 24%·속성 나머지 폭의 고정 열과 왼쪽·상단 정렬을 사용하며 좁은 화면의 내부 스크롤을 유지한다. 관계 조건은 중첩 카드·테두리 없이 출발 속성·실제 비교 연산·대상 속성을 내용 폭 기준으로 묶고 열 사이 24px 간격을 사용한다. 각 속성의 값 처리는 바로 아래에 두며 행 간격은 8px다. 좁은 화면에서는 기존처럼 세로로 읽고 조건이 여러 개일 때만 구분선을 사용한다. 의미 설명은 body-14로 유지한다. 비교 연산은 양쪽 속성 값과 같은 줄에 정렬하고 보라색 강조를 유지한다. 검사 결과 페이지 이동은 결과가 한 페이지를 넘을 때만 표시하며, 상세 안에서는 높이 32px의 작은 버튼과 중립색 현재 페이지를 사용한다. EQ는 두 처리 결과가 같으면 연결한다고 안내하며 다른 연산을 EQ로 가정하지 않는다. 변환은 기존 편집 화면의 한글 명칭과 인자를 표시하고 원본 조건식은 펼쳐 확인한다. 근거의 신뢰도·분석 번호와 지표 설명은 행을 나누어 읽는다.

- 상세 필터는 제안 출처·제안 종류·반영 상태만 제공하고 검토 상태는 상단 탭에서 선택한다. 상세 필터 안 검색·초기화 버튼은 두지 않으며 바깥 검색 적용이 검색어와 상세 조건을 함께 적용한다. 적용 조건 요약은 검색어 또는 추가 필터가 적용된 경우에만 표시한다. 검색 줄의 초기화는 공통 secondary 버튼을 사용한다. 검색어·제안 출처·제안 종류·반영 상태와 미적용 필터 입력을 비우고 첫 페이지로 이동하며, 선택한 검토 상태·객체 속성/매핑 탭·분석 범위는 유지한다.

- 연결 규칙 상단에서는 분석 관리 메뉴(최근 분석·변경 데이터 재분석·테스트 분석 삭제)를 표시하지 않는다. AI 관계 제안 받기와 현재 분석 진행 확인, 규칙 이력·검토·승인·반영은 유지한다.

- 연결 규칙은 상단에 AI 제안과 직접 제안·수동 검사 경로를 모으고, 상태·유형·검색·상세 필터를 그 아래에 둔다. 별도 소개나 진행 단계 UI는 추가하지 않는다.
- 후보 목록은 기본 240~272px, 1000px 이하에서는 220~240px로 상세의 가용 폭을 확보한다. 760px 이하에서는 기존처럼 세로로 재배치한다. 긴 이름은 줄바꿈한다. 후보 목록 페이지네이션은 높이 32px·버튼 최대 폭 28px·간격 2px로 최대 번호 5개와 이동 버튼을 한 줄에 표시하며, 좁은 목록에서는 버튼 폭을 균등하게 줄인다. 하단 건수·쪽수는 시각적으로 생략하고 스크린리더 안내는 유지한다. 기존 페이지 크기와 이동 동작을 유지한다.
- 상세는 규칙·상세 정의/대안, 제안 근거와 정합성 검사, 검토 결정 순서다. 근거와 검사는 1280px 이상에서 병렬로 읽고 작은 창에서는 순서대로 쌓는다. 원본과 대안은 기존 펼침 영역에서 확인한다.
- 병렬 영역의 검사 표본 표는 최소 720px 읽기 폭과 이름 있는 내부 가로 스크롤을 제공한다. 짧은 설비 코드·판정명과 표 헤더가 과도하게 잘리지 않게 하며 긴 원문 값은 셀 안에서 줄바꿈한다. 유형 선택 버튼은 보라 보조 면·경계와 본문색을 함께 써 대비를 확보한다.
- AI 신뢰도는 근거에서 설명하며 검사·검토·반영 상태와 구분한다. 반복 검사 요약은 생략하고 실제 검사 상태·표본·오류 복구를 그대로 제공한다. 반영 실패 사유는 상세 제목 바로 아래에 기본 노출한다.
- 표시 배치만 변경하며 사유 필수·1000자 한도, 대안 선택, 검사 조건, 즉시 결정 요청과 충돌/권한/네트워크 오류 복구는 유지한다. 시안의 가상 확인창이나 후보별 사유 보관은 도입하지 않는다.
- 검증 범위: 구성·선택·검색·필터·검사/결정 회귀는 자동 테스트로 확인한다. 실제 브라우저의 창 크기·확대·키보드 검증 결과는 해당 구현 작업 기록을 따른다.

### Action 정의 편집 배치

- 목록은 기존 4열과 필터·조회·페이지 이동을 유지한다. 필터·검색·초기화는 왼쪽에 묶고 Action 등록은 같은 행 오른쪽 끝에 분리한다. 검색은 보조 버튼, 등록은 주요 버튼이다. 좁은 창에서는 읽기 순서대로 재배치한다.
- 등록·수정은 기본 정보·실행 조건·입력 형식 탭으로 나눈다. 탭 이동만으로 입력·미완성 JSON·표 편집 모드를 초기화하거나 저장하지 않는다. 코드·Handler는 개발 연결 설정에서 확인하며, 신규 코드는 기본 정보에 둔다. 관리 작업은 기존 읽기 전용을 유지한다.
- 전체 입력을 검증하고 오류가 있는 탭·접힌 개발 설정을 열어 입력과 오류를 찾을 수 있게 한다. 필수 경고·차단 사유·통신 실패는 접힌 도움말에 숨기지 않는다. 저장이 차단돼도 탭으로 보존된 입력을 확인할 수 있다.
- 탭은 tablist·tab·tabpanel 연결과 선택 상태, 방향키·Home/End 탐색을 제공한다. 기존 API·rowVersion·서버 권한·저장 실패 입력 보존·중복 제출 방지는 유지한다.

## 10. 지원 범위와 접근성

- 정식 데스크톱 업무 지원은 1280 CSS px 이상, 대표 1440px, 추가 검증 1920px이다. 960px에서는 재배치·기능 접근을 확인한다. 모바일 전용 업무 지원을 추가하거나 기존 좁은 창 대응·접속을 제거하지 않는다.
- 기본 검증 브라우저는 데스크톱 Chrome·Edge다. Safari·Firefox의 정식 지원 추가는 이번 범위에 포함하지 않는다. 검증에는 버전·CSS viewport·실제 확대율을 기록한다.
- 기존 화면별 전환점·상세 폭을 유지한다. 표·관계도는 가용 폭, 폼·긴 본문은 읽기 폭을 확보한다. 좁은 창·확대 시 폼·행동을 재배치하고 필요한 영역 안에서 스크롤한다.
- 키보드로 메뉴·검색·표 행동·Dialog를 조작하고 이동·조회 후 포커스를 보존한다. label·오류 연결·ARIA를 유지하고 상태 변화를 보조 기술에 알리되 반복 낭독은 피한다.
- 브라우저 확대와 reduced-motion을 지원한다. 기존 공통 스피너 900ms linear·Button 전환 120ms는 no-preference 조건의 값을 유지한다. 새 전역 모션·그림자 스케일은 필요성이 확인된 뒤 다룬다.
- Button·Input·Select·Dialog·Table과 조회 → 근거 확인 → 규칙 검토 → 실행 결과 확인을 우선 점검한다. 긴 값·많은 관계·0건·미제공·처리·실패·권한 제한을 포함한다.
- 승인된 비민감 데이터 또는 구조·길이를 재현한 데이터를 사용한다. 코드의 ARIA·모의 테스트 통과·200% 확대 확인만으로 전체 접근성이나 운영 검증 완료를 선언하지 않는다.

## 11. 관리·변경 원칙

- 문서·공통 UI 관리, 기준·예외 최종 승인, 검증·수용과 기준 캡처 검토의 책임은 이 문서의 기준을 승인한 사용자 본인이다. 업무 의미 변경은 해당 기능 담당자도 함께 검토한다.
- 공통 기준을 변경할 때 이유·영향·예외를 함께 설명하고, 실제 구현·검증 범위를 구분한다. 상태별 캡처에는 화면·상태·데이터 조건·역할·창 크기·촬영일·코드 버전을 남긴다.
- 공통 기준과 예외를 코드·문서에서 함께 관리하고 대체된 규격은 유효 기준에서 제거한다. Markdown·코드·캡처·Git 이력을 사용하며 Storybook·Figma 신규 도입과 별도 디자인 시스템 버전은 보류한다.
- API·DB·권한·승인·업무 의미는 기존 명세를 따른다. Commit·Push·MR·Merge·운영 작업 권한은 프로젝트 협업 규칙을 따른다.
