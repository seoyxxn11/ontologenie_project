작성일: 2026-11-14 · UI/UX 절차 3단계(계획)

## 4단계 실행 결과 · 2026-11-14

사용자의 4단계 구현 요청으로 위 계획을 실행했다. 아래 계획 본문과 체크리스트는 승인 당시 기록으로 보존한다.

- `origin/develop @ 0ecd6691`에서 `feature/sources-summary-layout`을 준비하고 계획의 8개 파일을 수정했다. 이전 AI 화면 작업과 기존 미추적 자료는 보존했다.
- 상단 원천 선택·전체 너비 상세·상태 요약·5개 탭·기존 등록/수정 및 AI 제안 흐름을 구현했다. 선택 원천의 접속 상태는 기존 상세 query를 공유해 오래된 목록 상태와의 불일치를 수정했다.
- 디자인 시스템 규격을 반영하고 승인된 전체 너비 배치를 문서화했다. 4단계 polish를 적용했으며 탐지 예외를 추가하지 않았다.
- 최종 전체 테스트 81개 파일·1,126개, lint·format:check·build가 통과했다. 실제 로컬 React에서 4개 폭 × 5개 탭의 가로 넘침과 브라우저 오류는 0개였으며 MES 선택 후 AI 제안 대상도 MES로 유지됐다.
- 원천 0/1/120개·긴 이름·수집 실패·요약 조회 오류 및 좁은 화면의 선택 버튼 가시성을 가상 데이터로 확인했다. 운영 API·DB·실제 AI 실행·다른 브라우저는 미검증이다.
- 상세 명령·결과·초기 실패와 수정·캡처는 `output/sources-implementation/verification.md` 및 같은 디렉터리에 보존했다. 별도 5단계 QA·6단계 보고서·Commit·Push·MR·배포는 수행하지 않았다.

## 목표와 승인 범위

후속 사용자 결정: 원천 등록은 왼쪽의 원천 선택 버튼 바로 옆으로, AI 관계 제안은 개별 원천 상세 밖의 상단 오른쪽으로 이동한다. AI 버튼 문구는 ‘AI 관계 제안 받기’로 바꾸되 분석 대상 선택과 기존 기능은 유지한다. 최초 시안의 제목 옆 AI 배치는 이 결정으로 대체한다.

추가 사용자 결정: 계정 분리는 유지하며 정상 검사 결과는 한 줄로 요약하고 계정명·표·컬럼 수는 ‘계정별 상세’에 모은다. 실패는 기본 노출하며 수집 성공을 AI 성공으로 표현하지 않는다. 상단 접속 배지에 수집 용도를 명시한다. 구현 후 관련152개·최종 전체1,128개 테스트 및 lint·format·build를 통과했고, 실제 가상 데이터 화면에서 정상·계정별 실패·조회 오류와 기존5개 탭을 확인했다. 다른 반복 정보는 후보만 보고하고 유지했다.

이후 사용자 승인: CDC 시각·기준 설명을 상단 요약에만 남기고 성공 완료 시각 앞의 반복 문구를 제거했다. 원천명·실패 시각 의미·기존 수집 기능은 유지했다. 변경 후 전체1,128개 테스트와 lint·format·build를 통과했으며 실제1440/320px 화면에서 시각 값과 중복 제거를 확인했다.

5단계 요청에 따라 독립 디자인(A)·탐지/브라우저(B) 평가와 break-ui를 수행했다. 200자 이름에서 선택 버튼이 잘리는 문제와 성공 상태 전환의 live 안내 부족을 수정했다. 같은90조건 재검에서 단일 버튼 잘림20→0·가로 넘침0·페이지오류0, 전체1,128개 테스트·lint·format·build를 통과했다. 독립 재검에서 긴 이름 전체 표시와 실제 polling 중 같은 polite/atomic 상태 노드 유지를 확인했다. 세부 근거·제약·가상 데이터 전환기는 `output/sources-qa/`에 보존했다. Commit·Push·MR·6단계 결과보고서는 수행하지 않았다.

사용자가 선택한 상태 요약형을 실제 데이터 연결 화면에 적용한다. 대표 흐름은 등록된 ERP·MES 선택 → 접속·수집 상태와 데이터 확인 → AI 관계 제안이다. 반복 설명과 왼쪽 빈 열을 줄이고, 다음 행동과 필요한 상태를 먼저 보여 준다.

- 상단에 원천 이름·접속 상태가 함께 보이는 선택 버튼을 나란히 둔다. 선택 원천은 보라 보조 면·테두리·밑선과 `aria-pressed`로 구분한다.
- 아래 상세는 가용 콘텐츠 전체 너비를 쓴다. 패널 높이를 늘리거나 빈 행을 추가해 공간을 채우지 않는다.
- 접속 확인·최근 전체 읽기·CDC 마지막 반영 시각을 항상 표시한다. 설명만 ‘상태·시각 기준’에서 펼친다. 실패·조회 불가·권한 제한 안내는 기본 노출한다.
- 접속 정보·수집 대상·원천 표본·원천 매핑·수집 이력 5개 탭과 등록·수정·연결 재검사·수집·매핑·AI 제안 흐름을 유지한다.
- 선택 원천 제목 가까이에 기존 ‘이 원천으로 AI 관계 제안 받기’를 배치한다. 페이지 제목·소개·단계 표시·새 검색·새 페이지네이션은 추가하지 않는다.

사용자의 이번 요청은 3단계 진행과 디자인 시스템 대조다. 이 문서는 계획이며 실제 프론트엔드 수정·브랜치 생성·테스트 실행·Commit·Push·MR·Merge·배포를 수행한 기록이 아니다.

## Task 2: 원천 선택과 전체 너비 상세

- [ ] `fetchSources()`의 모든 페이지 조회와 원천 ID 기반 선택을 유지한다. ERP·MES는 대표 예시이며 실제 버튼은 서버의 원천 배열 전체에서 만든다. 다른 PostgreSQL·기존 CSV/문서 원천의 선택·이름·유형·상태도 유지한다.
- [ ] 선택 그룹·버튼에 접근 가능한 이름과 `aria-pressed`·`aria-controls="source-detail"`를 제공한다. 이름·상태는 직접 보이고 이름을 일괄 말줄임하지 않는다. 유형은 선택 원천의 접속 정보에서 계속 확인한다.
- [ ] 대표 2개 원천은 나란히 표시한다. 원천이 많을 때는 선택 영역에서 줄바꿈·기존의 제한된 내부 스크롤 접근을 유지해 상세를 끝없이 아래로 밀지 않는다. 새로운 숨김 메뉴·드롭다운·검색·원천 페이지네이션은 추가하지 않는다. 키보드로 모든 버튼과 선택 원천에 접근·스크롤할 수 있게 한다.
- [ ] `select(sourceId, nextTab)`과 `source`·`tab`·`register=1` URL 동작을 보존한다. 새로 등록한 원천 선택, 같은 ID 갱신, 브라우저 이동과 미저장 폼 보호를 유지한다.
- [ ] 상세의 가용 폭을 전부 사용한다. 왼쪽 목록 열·고정 폭·높이 맞춤용 빈 영역을 제거한다. 좁은 창에서 버튼·제목·행동·탭을 줄바꿈한다.
- [ ] 기존 AI 행동을 상세 제목 행으로 이동한다. `initialSourceId`, `onStarted`, `onEditScope`, `onRegister`와 실제 분석 결과 이동은 유지한다.
