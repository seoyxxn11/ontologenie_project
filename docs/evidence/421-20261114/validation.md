## 변경과 계약 대조

- 기본 `npm run dev`는 `mock`, `npm run dev:api`는 `real`. 명시한 `VITE_API_MODE=mock|real`이 우선하며 다른 값은 실패한다. 배포 빌드는 설정과 무관하게 실제 API만 사용한다.
- 실제 모드는 같은 출처 `/api/v1`을 `API_PROXY_TARGET`(기본 `http://localhost:8080`)으로 전달한다. 대상의 계정·경로·쿼리·프래그먼트는 거절한다. TLS 검증·세션·CSRF는 약화하지 않으며 브라우저에 이 서버용 환경값을 주입하지 않는다.
- 실제 모드 시작 전 이 앱의 `mockServiceWorker.js` 등록만 해제한다. 현재 문서도 제어 중이면 해제 후 새로고침하고 앱을 시작한다. 다른 워커는 유지한다. 모의 모드의 알 수 없는 API는 실제 서버로 통과시키지 않으며 정적 파일은 통과시킨다.
- **026:** 최신 `PropertyController.findProperties`/`PropertyService.findViewableProperties`는 ADMIN에 전체 정의, 비관리자에게 허용 유형의 비민감 속성을 제공한다. 이전 점검의 ADMIN 전용 설명은 적용하지 않았다. 속성 응답은 실제 DTO 필드와 401/403/404 계약을 따른다. 모의 역할 범위는 운영 정책이 아닌 가상 자료 예시다.
- 모의 `/objects/types`의 기존 유형 3~8과 속성 정의 응답 범위를 일치시켰다. 대량 예시는 1~27 유형을 사용하며 중복 속성 핸들러의 우선순위 우회를 제거했다.
- **021·034·037:** ADMIN 제한·페이지 분할/메타·빈 쪽·잘못된 페이지를 확인했다. 021의 이름/코드 검색을 반영했다.
- **040·102:** 매핑 미리보기의 관리자 제한을 반영했다. 같은 102 경로의 SAMPLE 핸들러는 해당 ID가 없을 때 MAPPING_PREVIEW에 넘기는 의도된 체인이다. 두 종류의 실제 조회 결과와 비관리자 차단을 회귀 검사한다.
- **041:** `TransformFunction.ALL`/`TransformFunctionResponse`의 10개 변환, `argument.name`, `inputTypes`, `outputType`, `example.step/input/output`을 반영했다. 프론트에서 실제 변환 엔진을 새로 구현하지 않는다.
- 매핑 버전 충돌은 `409 VERSION_CONFLICT`, 대상 없음은 `404 RESOURCE_NOT_FOUND`와 공통 오류 필드를 유지한다. 관리자 화면 성공 경로의 기존 테스트는 ADMIN 계정을 명시하고, 공통 기본 계정·조회 역할 테스트는 유지했다.

## Chrome 검증

- 로컬 모의 ADMIN 로그인 후 기존 수주 유형의 속성 조건(수주 번호·상태)이 오류 없이 나타남을 확인했다. [화면](mock-admin.png).
- 로컬 모의 VIEWER 로그인 후 설비 속성 조건에 일반 속성이 나타나고 민감 예시인 구매 가격은 나타나지 않음을 확인했다. [화면](mock-viewer.png).
- 같은 주소에서 모의 모드 → 실제 모드로 서버를 재시작하고 새로고침했다. 모의 VIEWER 로그인이 복원되지 않았으며, 실제 백엔드가 없는 상태의 `/auth/me`는 서버 오류 안내로 나타났다. 모의 성공 응답으로 대체되지 않았다. [화면](real-api-unavailable.png).
- 기존 운영 관리자 세션으로 **GET만** 읽었다: 021(page=0,size=1)의 `meta.page/size/totalElements/hasNext`를 확인했고, 반환된 설비 유형 ID 1의 026에서 실제 15개 DTO 필드를 확인했다. 041은 위 10개 변환과 인자·자료형·예시 필드를 실제 응답에서도 확인했다. 업무 속성 값·비밀번호·쿠키·토큰을 복사하거나 저장하지 않았다.

## 리뷰와 수정

- 별도 컨텍스트의 읽기 전용 리뷰어가 `.ai/workflows/code-review.md` 기준으로 검토했다.
- 1차: **Critical 0 / Major 1 / Minor 1**.
- Major: 기존 가상 유형 선택지와 속성 응답 범위가 달라 새로 404가 발생. 유형 3~8 정의와 역할 범위를 맞추고 ADMIN·VIEWER가 모든 기존 선택지의 속성을 조회하는 재현 검사를 추가했다.
- Minor: 041 목록이 기존 4개 함수·축약 필드에 머묾. 최신 10종·인자·자료형·예시로 보완하고 응답 계약 검사를 추가했다.
- 사용자 요청의 '검증·리뷰해서 minor까지 고친 뒤' 범위에서 수정했다. 같은 별도 리뷰어의 최종 재리뷰는 **Critical 0 / Major 0 / Minor 0**이다. 변경 코드·서버 계약·호출부·검증 문서·PNG 3개를 정적으로 확인했으며 테스트 실행 결과를 독립 재현한 리뷰는 아니다. AI 리뷰는 사람 승인을 대신하지 않는다.

## 미검증·후속

- 실제 업무 백엔드의 로그인·CSRF·조회 역할 세션을 로컬 프록시와 연결한 전체 E2E는 미검증이다. 로컬에는 업무 백엔드가 없으며, 브라우저 검사의 역할별 성공 경로는 모의 계정이다.
- 운영의 비관리자 026 가림·042/420 정책은 이번에 재검증하거나 변경하지 않았다. 실제 관리자 GET 응답과 코드 대조를 역할 전체 검증으로 취급하지 않는다.
- 실제 매핑 쓰기·원천 수집·승인·삭제, 장시간 반복 안정성·실제 재시도 횟수·모든 도메인의 민감값 노출은 미검증이다.
- Agent 등 팀원 담당 개별 모의 시나리오와 대상 밖 API의 모든 입력 검증까지 동일한 서버 구현으로 만드는 작업은 포함하지 않는다.
- MR의 사람 리뷰·병합·병합 후 운영 확인은 후속이다. Jira 완료 상태나 병합 후 확인 체크는 변경하지 않는다.
