# 410 문구·표시 오류 정리 검증

- Jira: S15P31C106-410. 담당·보고자 손주연, 3포인트.
- 브랜치: `fix/410-ui-labels`, MR 대상 `develop`.
- 사용자 지정 순서대로 `5cce1ab` 기준에서 먼저 구현하고, 이후 fetch한 최신 develop `d39eb37`을 fast-forward 반영했다. 겹치는 파일과 충돌은 없었고 409의 변경은 develop에서 가져왔다.

## 범위와 근거

| 항목 | 처리 |
| --- | --- |
| 검색 예시 | `PR-03` 대신 `P101`을 표시한다. Chrome의 기존 운영 세션에서 읽기 전용 P101 검색을 실행해 전체 유형 155건과 설비 P101 결과를 확인했다. |
| 복합 키 | 목록·상세·편집 창의 키 조합을 `+`로 표시하고 선택 순서는 유지한다. 변환 단계와 관계 방향의 화살표는 유지한다. |
| 내부 규칙 코드 | 기존 `GET /api/v1/ontology/rules`가 반환한 현재 규칙의 description, 없으면 linkTypeName을 표시한다. 코드 기반 임의 번역·원문 추가 조회는 하지 않는다. 이름 미제공·조회 실패를 구분하며 실패 후 이전 캐시 이름은 표시하지 않는다. |
| 문제 건수 | 상단은 필터와 무관한 해결 포함 전체 건수, 문제 목록은 현재 필터의 조회 결과 건수로 명시한다. 전체 meta가 없으면 현재 페이지 길이를 전체 건수로 대신하지 않는다. |
| 팝업 버튼 | 원본·연결 근거 버튼의 ↗는 현재 develop에서 이미 제거돼 있어 변경 없이 회귀 검증한다. 실제 Link의 이동 표시는 이번 범위에서 변경하지 않는다. |
| 관리자 중복 | 계정 displayName과 역할 이름이 같으면 역할을 반복 표시하지 않는다. 서로 다른 이름·역할은 유지한다. |
| viewer 계정 | 계정 레코드·이름·역할·권한을 변경하지 않는다. 테스트의 합성 계정 이름 보존을 확인한다. |

규칙 이름은 목록의 최신 개정본 기준 표시 이름이며 과거 검사 시점 이름을 복원한 값은 아니다. 관련 근거는 `docs/rule-revision.md`와 `RuleSummaryResponse`, `RuleRevisionController`의 기존 읽기 계약이다. 문제 목록/상세는 기존 065·066 흐름을 유지하며 서버 API·DTO·DB·ERD를 변경하지 않는다.

연결된 Notion 기능 명세 페이지는 404로 읽지 못했다. 사용자 전달 QA, 저장소 문서와 현재 코드를 근거로 작업했고 읽지 못한 명세 내용을 추정하지 않았다.

## 검증

- 최신 develop 반영 전 관련 화면 4개 파일 121개 테스트 및 규칙 이름 표시 9개 테스트 통과. TypeScript 검사 통과.
- 최신 develop 반영 후 `vitest run --maxWorkers=4 --reporter=dot`: **74개 파일·1,057개 테스트 통과**.
- `npm run lint`, `npm run build`, `npm run format:check` 통과. 중복 key·React act·500kB 초과 번들 경고 없음. 최대 JS 425.58kB.
- 별도 서브에이전트 정적 리뷰: Critical 0 / Major 0 / Minor 0. 실제 브라우저·테스트 실행은 작성 세션이 담당했으며 AI 리뷰는 사람의 승인을 대신하지 않는다.
- 운영 Chrome에서는 검색만 읽기 전용으로 확인했다. 수정 UI는 자동 화면 테스트로 검증했으며 이번 브랜치를 운영 배포하거나 운영 화면에 반영해 검증한 것은 아니다.
- 운영 데이터 변경, 운영 배포, 서버 정책 검증을 위한 쓰기 요청은 실행하지 않는다. 백엔드 변경이 없어 백엔드 테스트·전체 build는 이번 작업에서 실행하지 않는다.

## 변경 경계

377의 삭제된 held_item 기능을 복구하지 않는다. 384 및 390~397의 분류·가림·그룹/민감도 편집, Agent 가드레일, 원천 SQL·CDC·배치·인프라 등 팀원 담당 기능을 수정하지 않는다. Jira 완료 전환·MR 병합·운영 배포는 별도 사람의 판단으로 남긴다.
